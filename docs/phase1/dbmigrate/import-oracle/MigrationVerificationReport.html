Scope and method

The Linux machine cannot reach the SQL Server database, so the comparison is made against source-metadata.json: a record written on Windows at export time from the source catalog and the same in-memory rows the SQL files were generated from, by a separate code path. The tool starts an Oracle container with no published network port, checks the files are the ones the record describes, creates a schema-only account (no password; nobody can log in as it), runs the schema and data scripts in it with SQL*Plus (stopping at the first error), and runs the checks below in PL/SQL inside the container as SYS through operating-system authentication. No data leaves the container and no password is kept.

Row content is compared with a fingerprint: every row of a table is written in one fixed text form (integers in decimal, true/false as 1/0, timestamps to the millisecond, text as the hex of its UTF-8 bytes, NULL distinct from empty text), the rows are sorted, and the whole table is hashed with SHA-256. A single changed character anywhere in a table changes its hash. The form is database-independent, so the fingerprints recorded at export equal those of the PostgreSQL export of the same data.

Rule tests

These try things the database must allow or refuse, each between a savepoint and a rollback to it. Test rows use explicit ids far above the data, so no identity sequence moves; the sequences are read first (from DBA_SEQUENCES.LAST_NUMBER, without drawing a value) and the last check confirms nothing was left behind. Oracle-specific findings are recorded here too: a BOOLEAN column silently converts numbers and words such as 'yes' but rejects 'maybe'; text written in the export's CHR/UNISTR literal form comes back byte for byte; and with MAX_STRING_SIZE = STANDARD a VARCHAR2(2000 CHAR) value is also limited to 4,000 bytes.

Known differences from the legacy database

  • Identifiers are lowercase snake_case in the SQL (for example CreatedAt becomes created_at; User_Id becomes user_id) and Oracle stores them in upper case; foreign key and index names are renamed too. Data values are never lowercased.
  • datetime columns become TIMESTAMP(3) without time zone and keep the source values exactly; it is not known whether the legacy application stored UTC or local times (only LockoutEndDateUtc is UTC by name), so no zone conversion is made.
  • SQL Server compared text case-insensitively; Oracle is case-sensitive. Username uniqueness is enforced case-insensitively by a function-based unique index on CASE WHEN deleted_at IS NULL THEN LOWER(name) END (Oracle has no partial index), so authentication must compare LOWER(name) = LOWER(input). Role names use a plain case-sensitive unique index.
  • bit columns become the native BOOLEAN type (Oracle 23ai and later; not available on 19c); the identity columns become GENERATED BY DEFAULT AS IDENTITY and the data supplies explicit ids (each identity is restarted after the last issued value once the data is loaded).
  • Oracle stores an empty string as NULL. The export refuses a source that contains an empty string (there is none), because loading it would silently turn it into NULL.
  • ON DELETE NO ACTION is written by leaving the clause out: Oracle rejects the words, and its default already means no action.
  • nvarchar(n) becomes VARCHAR2(n CHAR): the length is in characters, but a VARCHAR2 value is also limited to 4000 bytes unless the database has MAX_STRING_SIZE=EXTENDED, so multi-byte text near the limit can overflow.
  • The SQL files are pure ASCII: control characters are written as CHR(n) and non-ASCII characters as UNISTR('\XXXX'), so loading does not depend on the client character set.
  • Index names that were duplicated across tables in SQL Server (for example IX_UserId) were prefixed with the table name, then renamed to snake_case.
  • Excluded on purpose: __MigrationHistory (Entity Framework migration history, not application data).
  • Credentials were invalidated, not carried over (see Credential sanitization).

What this verification is and is not

  • It compares the database with a record made at export, not with the live SQL Server database, which this machine cannot reach. The record was produced by a separate code path from the SQL, so this is a real end-to-end check of the export and the load.
  • It guards against mistakes, not tampering: someone with write access could change both the record and the SQL files.
  • Timestamps have no time zone, and whether the legacy application stored UTC or local time is unknown; no conversion was made.
  • Usernames are unique regardless of case only through the function-based index on LOWER(name), so sign-in must compare LOWER(name) = LOWER(:input).
  • Oracle 23ai or later only (BOOLEAN, multi-row INSERT); Oracle 19c would need a different export.
